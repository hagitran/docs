# WhetData Ult API Documentation

## Introduction

The WhetData Ult API provides powerful text processing and classification capabilities for e-commerce product descriptions and other text content. Our API enables you to validate text quality, receive actionable improvement suggestions, and ensure your content meets high standards for conversion optimization.

### Key Features

- **Text Classification** - Analyze and validate text quality against customizable rulesets
- **Smart Nudges** - Get AI-powered suggestions to improve your content
- **Flexible Rulesets** - Use predefined, custom rulesets or a combination of both for domain-specific validation
- **Rate Limiting** - Built-in rate limiting for fair usage and system stability

### Base URL

```
https://whetdata.com/api/ult
```

### API Versioning

The current API version is `1.0.0`. We follow semantic versioning and maintain backwards compatibility within major versions.

## Authentication

The WhetData Ult API uses API keys to authenticate requests. You can obtain your API key from your WhetData dashboard.

### API Key Format

API keys follow the format: `whet_<uuid>`

Example: `whet_123e4567-e89b-12d3-a456-426614174000`

### Including Your API Key

Include your API key in the `x-api-key` header with every request:

<CodeGroup>

```bash cURL
curl -X POST https://whetdata.com/api/ult \
  -H "x-api-key: whet_your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "classification",
    "ruleset": "product_descriptions",
    "text": "Your text here"
  }'
```


```python Python
import requests

url = "https://whetdata.com/api/ult"
headers = {
    "x-api-key": "whet_your_api_key_here",
    "Content-Type": "application/json"
}
payload = {
    "action": "classification",
    "ruleset": "product_descriptions",
    "text": "Your text here"
}

response = requests.post(url, headers=headers, json=payload)
print(response.json())
```

## Rate Limits

To ensure fair usage and system stability, the API enforces the following rate limits to each key by default:

| Limit Type | Requests | Time Period | Reset            |
| ---------- | -------- | ----------- | ---------------- |
| Daily      | 1,000    | 24 hours    | Midnight UTC     |
| Monthly    | 30,000   | 30 days     | 1st of month UTC |

However, this can be changed on the Dashboard.

### Rate Limit Headers

Every response includes rate limit information:

```json
{
  "rateLimit": {
    "dailyRemaining": 950,
    "monthlyRemaining": 28500
  }
}
```

### Rate Limit Exceeded

When you exceed the rate limit, you'll receive a `429` status code:

```json
{
  "error": "Rate limit exceeded",
  "message": "Daily rate limit of 1000 requests exceeded",
  "rateLimit": {
    "dailyRemaining": 0,
    "monthlyRemaining": 28500,
    "resetTime": "2025-01-15T00:00:00Z"
  }
}
```

---

Warnings will be sent when approaching rate limits.

## Actions

The API supports three main actions through the same endpoint: `classification`, `nudges`, and `clean`.

## Classification

Classify and validate text quality against specified rulesets. This action analyzes your text and provides a quality score, validation result, and detailed reasoning.

### Request

**POST** `/api/ult`

#### Headers

| Header         | Type   | Required | Description                                 |
| -------------- | ------ | -------- | ------------------------------------------- |
| `x-api-key`    | string | Yes      | Your API key                                |
| `Content-Type` | string | Yes      | `application/json` or `multipart/form-data` |

#### Body Parameters

| Parameter   | Type   | Required | Default | Description                                   |
| ----------- | ------ | -------- | ------- | --------------------------------------------- |
| `action`    | string | Yes      | -       | Must be `"classification"`                    |
| `ruleset`   | string | Yes      | -       | Name of the ruleset to use for classification |
| `text`      | string | Yes      | -       | The text to classify (max 5,000 characters)   |
| `threshold` | number | No       | 0.7     | Quality threshold for validation (0.0 to 1.0) |

### Request Example

```bash
curl -X POST https://whetdata.com/api/ult \
  -H "x-api-key: whet_your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "classification",
    "ruleset": "product_descriptions",
    "text": "Discover our premium wireless headphones featuring active noise cancellation, 30-hour battery life, and crystal-clear audio quality. Perfect for music lovers and professionals.",
    "threshold": 0.8
  }'
```

### Response

#### Success Response (200 OK)

```json
{
  "success": true,
  "action": "classification",
  "ruleset": "product_descriptions",
  "result": {
    "valid": true,
    "confidence": 0.92,
    "score": 0.85,
    "reason": "Text meets quality standards with strong feature descriptions and emotional triggers",
    "threshold": 0.8
  },
  "rateLimit": {
    "dailyRemaining": 999,
    "monthlyRemaining": 29999
  }
}
```

#### Response Fields

| Field               | Type    | Description                                      |
| ------------------- | ------- | ------------------------------------------------ |
| `success`           | boolean | Whether the request was successful               |
| `action`            | string  | The action performed (`"classification"`)        |
| `ruleset`           | string  | The ruleset used for classification              |
| `result`            | object  | Classification results                           |
| `result.valid`      | boolean | Whether the text meets quality standards         |
| `result.confidence` | number  | AI confidence in the classification (0.0 to 1.0) |
| `result.score`      | number  | Quality score of the text (0.0 to 1.0)           |
| `result.reason`     | string  | Explanation of the classification                |
| `result.threshold`  | number  | The threshold used for validation                |
| `rateLimit`         | object  | Current rate limit status                        |

### Use Cases

- **Quality Assurance** - Validate product descriptions before publishing
- **Content Moderation** - Ensure content meets brand guidelines
- **A/B Testing** - Compare quality scores of different content versions
- **Automated Workflows** - Gate content publication based on quality scores

## Nudges

Generate actionable improvement suggestions for your text. This action analyzes your content and provides specific, prioritized recommendations to enhance quality and conversion potential.

### Request

**POST** `/api/ult`

#### Headers

| Header         | Type   | Required | Description                                 |
| -------------- | ------ | -------- | ------------------------------------------- |
| `x-api-key`    | string | Yes      | Your API key                                |
| `Content-Type` | string | Yes      | `application/json` or `multipart/form-data` |

#### Body Parameters

| Parameter    | Type   | Required | Description                                   |
| ------------ | ------ | -------- | --------------------------------------------- |
| `action`     | string | Yes      | Must be `"nudges"`                            |
| `ruleset`    | string | Yes      | Name of the ruleset to use for analysis       |
| `text`       | string | Yes      | The text to improve (max 5,000 characters)    |
| `max_nudges` | number | Yes      | Maximum number of nudges to generate (min: 1) |

### Request Example

```bash
curl -X POST https://whetdata.com/api/ult \
  -H "x-api-key: whet_your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "nudges",
    "ruleset": "product_descriptions",
    "text": "This product is good and works well.",
    "max_nudges": 3
  }'
```

### Response

#### Success Response (200 OK)

```json
{
  "success": true,
  "action": "nudges",
  "ruleset": "product_descriptions",
  "max_nudges": 3,
  "nudges": [
    {
      "type": "Technical Specifications",
      "suggestion": "Add specific dimensions",
      "priority": "high"
    },
    {
      "type": "Feature Benefits",
      "suggestion": "Highlight unique advantages",
      "priority": "high"
    },
    {
      "type": "Emotional Triggers",
      "suggestion": "Include lifestyle benefits",
      "priority": "medium"
    }
  ],
  "rateLimit": {
    "dailyRemaining": 998,
    "monthlyRemaining": 29998
  }
}
```

#### Response Fields

| Field                 | Type    | Description                                    |
| --------------------- | ------- | ---------------------------------------------- |
| `success`             | boolean | Whether the request was successful             |
| `action`              | string  | The action performed (`"nudges"`)              |
| `ruleset`             | string  | The ruleset used for analysis                  |
| `max_nudges`          | number  | Maximum nudges requested                       |
| `nudges`              | array   | Array of improvement suggestions               |
| `nudges[].type`       | string  | Category of the nudge                          |
| `nudges[].suggestion` | string  | Actionable improvement suggestion (2-4 words)  |
| `nudges[].priority`   | string  | Priority level (`"high"`, `"medium"`, `"low"`) |
| `rateLimit`           | object  | Current rate limit status                      |

## Rulesets

Rulesets define the criteria used for text classification and nudge generation. Each ruleset is tailored for specific content types and industries.

### Available Rulesets

| Ruleset Name           | Description                                            | Best For                                         |
| ---------------------- | ------------------------------------------------------ | ------------------------------------------------ |
| `product_descriptions` | E-commerce product description optimization            | Online retail, marketplaces                      |
| `marketing_copy`       | Marketing and advertising content                      | Ad campaigns, landing pages                      |
| `technical_docs`       | Technical documentation standards                      | API docs, user manuals                           |
| `reviews`              | Used to elicit insightful and honest customer reviews. | Reviewing of products, places, things, people... |

### Custom Rulesets

Custom rulesets can be created on the dashboard. They will only be accessible to API keys created in the same project as the ruleset.

### Hybrid Rulesets

This acts as a form of “fine-tuning” for available rulesets. It harnesses our industry knowledge and vast database while adapting to the specific needs of your product.

## Error Handling

The API uses standard HTTP status codes and returns detailed error messages.

### Status Codes

| Status Code | Description                                           |
| ----------- | ----------------------------------------------------- |
| `200`       | Success - Request completed successfully              |
| `400`       | Bad Request - Invalid parameters or malformed request |
| `401`       | Unauthorized - Missing or invalid API key             |
| `404`       | Not Found - Ruleset not found                         |
| `429`       | Too Many Requests - Rate limit exceeded               |
| `500`       | Internal Server Error - Server-side error             |

### Error Response Format

```json
{
  "error": "Error type",
  "message": "Detailed error description",
  "details": {
    "field": "Additional context"
  }
}
```

### Common Errors

#### Invalid API Key

```json
{
  "error": "Unauthorized: Invalid API key"
}
```

#### Missing Required Field

```json

}
```

#### Ruleset Not Found



## Security

### Input Sanitization

All inputs are sanitized to prevent injection attacks:

- HTML/Script characters are removed
- JavaScript protocols are stripped
- Maximum input lengths are enforced
- Special characters are escaped

### Secure Comparison

API keys are compared using timing-safe comparison to prevent timing attacks.

All API endpoints require HTTPS. Requests over HTTP will be rejected.

The API supports CORS with the following headers:

- `Access-Control-Allow-Origin: *`

## Best Practices

### 1. Optimize Your Requests

- **Batch Processing**: Process multiple texts efficiently by implementing queue systems
- **Threshold Tuning**: Adjust threshold values based on your quality requirements

### 2. Handle Errors Gracefully

```javascript
async function safeClassify(text) {
  try {
    const result = await classifyText(text);
    return result;
  } catch (error) {
    if (error.response?.status === 429) {
      // Handle rate limiting - implement exponential backoff
      await sleep(60000); // Wait 1 minute
      return safeClassify(text);
    } else if (error.response?.status === 401) {
      // Handle authentication error
      console.error('Invalid API key');
      return null;
    }
    throw error;
  }
}
```

### 3. Implement Retry Logic

```python
import time
from typing import Optional

def classify_with_retry(text: str, max_retries: int = 3) -> Optional[dict]:
    for attempt in range(max_retries):
        try:
            return classify_text(text)
        except requests.exceptions.HTTPError as e:
            if e.response.status_code == 429 and attempt < max_retries - 1:
                # Exponential backoff
                wait_time = 2 ** attempt
                time.sleep(wait_time)
                continue
            raise
    return None
```

### 4. Monitor Your Usage

- Track API usage against your limits
- Set up alerts for approaching limits
- Implement usage dashboards for visibility

### 5. Validate Inputs Client-Side

```javascript
function validateInput(text, ruleset) {
  const errors = [];
  
  if (!text || text.trim().length === 0) {
    errors.push('Text is required');
  }
  
  if (text.length > 5000) {
    errors.push('Text exceeds maximum length of 5000 characters');
  }
  
  if (!ruleset) {
    errors.push('Ruleset is required');
  }
  
  return errors;
}
```

# FAQs

### Q: Can I use multiple rulesets in a single request?

A: Currently, each request supports one ruleset. For multiple rulesets, make separate API calls.

### Q: What's the maximum text length?

A: The maximum text length is 5,000 characters. For longer texts, consider splitting them into chunks.

### Q: How often are rulesets updated?

A: Rulesets are continuously improved based on performance data and customer feedback. Updates are seamless and don't require any changes to your integration.

### Q: Can I get historical API usage data?

A: Yes, historical usage data is available in your dashboard for the past 90 days.

### Q: Is there a sandbox environment?

A: A sandbox environment is planned for Q2 2025. Currently, we recommend using a separate API key for development.

### Q: How do I increase my rate limits?
